# Area Activity Analytics and QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist every detectable BAI-KIEM track–zone session as lightweight metadata so Gemini can report allowed/violating activity and generate evidence clips only after an explicit user click.

**Architecture:** Add an independent `area_activity_sessions` persistence path fed by existing annotated detections, leaving the violation state machine and alerts authoritative and unchanged. Node exposes bounded activity queries, read-only Gemini tools, and an additive deferred-evidence contract; Python reuses the existing clip generator for explicit activity clip requests. Local-video event signatures make replay and retry idempotent.

**Tech Stack:** PostgreSQL/Neon, Prisma 5.19, Node.js/Express/TypeScript, Python 3.11+ with asyncio/asyncpg, React 19/Vite, Gemini `gemini-3.5-flash-lite` function calling.

## Global Constraints

- One activity session is one tracked registry object entering and leaving one BAI-KIEM zone; overlapping zones create separate sessions.
- Counts mean entry sessions (`lượt`), never unique physical vehicles.
- Record all detectable registry labels and preserve `ALLOWED` versus `VIOLATION`.
- Do not run another detector or block frame processing on database/network I/O.
- Do not change existing Gate event, Area violation, alert, settings, training, or ready-clip behavior.
- Local-file replay, manual seek, and queue retry must not add another count for the same source event.
- RTSP/live confirmed re-entry creates a new session.
- No MP4 is generated by detection, persistence, Gemini tools, QA answer creation, history hydration, or `<video src>` assignment.
- Clip generation begins only through explicit `POST /api/v1/area-activities/:id/clip`.
- `Hôm nay` uses `Asia/Bangkok`; open durations are provisional.
- Never return filesystem paths, RTSP credentials, stack traces, Gemini keys, or database secrets.
- Design authority: `docs/superpowers/specs/2026-08-27-area-activity-analytics-qa-design.md`.

- `backend/python-worker/detection/activity_event_queue.py`: bounded retry queue isolated from violation delivery.

- `backend/python-worker/detection/event_clip_service.py`: reuse the generator through a persistence adapter for violation or activity records.
- `backend/python-worker/main.py`: activity clip HTTP endpoints.
- `backend/node-api/src/routes/areaActivities.ts`: activity list and lazy clip request/status endpoints.
- `backend/node-api/src/services/areaActivityClipService.ts`: Node-to-worker activity clip client and violation delegation.
- `backend/node-api/src/ai/tools.ts`: three read-only activity tools and deterministic aggregation.
- `backend/node-api/src/ai/gemini.ts`: carry one deferred evidence item beside existing ready clips.

- `backend/node-api/src/routes/qa.ts`, `backend/node-api/src/routes/chat.ts`: persist and return activity evidence.
